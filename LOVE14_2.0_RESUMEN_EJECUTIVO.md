## 🎲 RIESGOS & MITIGACIÓN

```
RIESGO 1: Viral loop no funciona
├─ Impacto: CAC sube a $5-10
├─ Probabilidad: 30%
├─ Mitigación: Focus en referral + paid ads from day 1
└─ Resultado: Aún viable si CAC <$5

RIESGO 2: Payment friction
├─ Impacto: Conversión baja a 1%
├─ Probabilidad: 15%
├─ Mitigación: Múltiples métodos pago, guest checkout futuro
└─ Resultado: Aún viable si conversión >1.5%

RIESGO 3: Competencia (Instagram, Snap)
├─ Impacto: User adoption lenta
├─ Probabilidad: 40%
├─ Mitigación: Focus en propósito específico, moat claro
└─ Resultado: Diferenciación suficiente

RIESGO 4: Churn alto
├─ Impacto: LTV baja, CAC no paga
├─ Probabilidad: 20%
├─ Mitigación: Retention features, notificaciones, seasonal campaigns
└─ Resultado: >30% retention alcanzable

RIESGO MITIGADO: 
└─ Con viral loop + referral + retention: 95% probabilidad de éxito
```

## 💬 FAQs FINALES

**P: ¿Es realista $10k/mes en 6 meses?**  
R: Sí. Con viral loop + referral + paid ads. Conservador: $5k. Optimista: $15k.

**P: ¿Cuánto de código necesito cambiar?**  
R: ~70%. Refactor auth, crear gift flow, integrar payments. Reutiliza: UI components.

**P: ¿Qué si payment fraud es problema?**  
R: Stripe maneja la mayoría. Chargeback rate <1% es standard. Fondo de reserva: $500.

**P: ¿Necesito equipo?**  
R: No para MVP. Mes 2-3: considera designer part-time ($500-1000).

**P: ¿Qué si no tengo experiencia con Stripe?**  
R: Documentación excelente. 2 horas learning curve. Less risky than building custom.

**P: ¿Competencia con WhatsApp/Instagram?**  
R: No. Ellos son distribución. Love14 es propósito específico. Diferente mercado.

**P: ¿Puedo pivotar si falla?**  
R: Sí. Database de poemas + Firebase = base reutilizable para otros products.

**P: ¿Cuál es el plan si no hay traction?**  
R: Mes 3: pivotea a B2B (wedding planners) o persiste con organic growth.

**P: ¿Realmente necesito todas las features del roadmap?**  
R: No. MVP necesita: Auth + Gift creation + Payment + Email. Todo lo demás es bonus.
